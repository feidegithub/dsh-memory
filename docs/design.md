## 0. 一句话

给 DSH 加一个**会遗忘、但永不删除**的记忆插件：记忆分五层（上下文 → 常驻核心 → 会话热区 → 长期库 → 原始日志），
写入时按"显著性"定强度，**常用越提越牢、久置逐渐变淡**；回忆时从快到慢逐层下沉，
**60 秒内想不起来就当作忘了**——先应一声，想起来了再接着回；联想只靠规则，不偷偷调模型。

## 1. 现状盘点（为什么值得做）

| 现状 | 事实 | 问题 |
|---|---|---|
| 跨会话记忆 | 只有 `AGENTS.md` 这类静态文件 | 只有一层；要人手写；不会衰减、不会回忆 |
| 历史会话 | 62 个文件 / 5.6 MB，`session-query-sqlite` 全文索引已启用 | **数据都在，但没有"主动回忆"的入口**，只能靠我手动 grep |
| 插件层记忆 | 只有 `dsh-douyin-scroll/lib/memory.mjs`（记小满/使用者的 facts） | 是私房实现，不成体系，别的插件用不上 |
| 内置记忆插件 | 无 | 需要新写 |
| 插件可 import 的包 | profile 只 hoist 了 `schemastery`、`cosmokit` | **不能**直接 import `dsh-storage-domain` 等；只能用 `ctx.*` 服务 |

结论：**不是从零造记忆，而是给已有日志加"索引层 + 分层召回 + 遗忘曲线"**。这是本方案能落地的根本原因。

## 2. 目标 / 非目标

### 目标
1. 跨会话记住：你是谁、你在意什么、做过什么决定、踩过什么坑。
2. 回忆**分快慢**：常用的事"张口就来"，不常用的事要"翻一下"。
3. **遗忘 ≠ 删除**：低强度条目默认不出现在结果里，但仍可从磁盘捞回。
4. **回忆有时间尺度**：40 毫秒想起 vs 翻了半分钟才想起，是两种不同的记忆；一分钟还想不起来，就是忘了。
5. 可审计、可纠正、可一键忘记：我能看到"我为什么记得这条"。
6. 成本可控：常驻注入有硬上限，深挖按需触发。

### 非目标（这一版不做）
- 不做向量数据库 / 本地 embedding（本机无 embedding 服务，先靠倒排 + 关键词扩展）。
- 不做"人格"或"情感"建模，不做记忆的图形化知识图谱（M3 之后再议）。
- 不替代 `AGENTS.md`（章程仍是静态只读的最高优先级），记忆是它的**动态补充**。
- 不做云端同步；记忆只在本机。

## 3. 核心映射：人脑 → 系统

| 人脑 | 本系统 | 载体 | 典型耗时 |
|---|---|---|---|
| 寄存器 / 正在想的事 | **L0 工作记忆** | 当前 prompt 上下文窗口 | — |
| CPU 内部缓存（下意识就想到） | **L1 常驻核心** | 每步自动注入的 `core profile`（≤600 token） | 0 |
| 内存（稍想一下） | **L2 会话热区** | 当前会话 + 近 7 天摘要 + 预取结果（≤1200 token） | ~5 ms |
| 硬盘（要翻找） | **L3 长期库** | 提炼条目 + 倒排索引 | ~50 ms |
| 深挖硬盘 / 翻旧账 | **L4 原始日志** | 全部历史会话（`sessionQuery` 全文索引） | 1–3 s |
| 绞尽脑汁联想 | **L5 联想阶梯** | 换角度重查：同义/别名/上位词/按人按时间/读候选全文 | 3–60 s |
| 遗忘 | **衰减 + 降层 + 超时** | `strength` 随时间下降；**60 秒窗到点即判忘了** | — |
| 事后突然想起 | **补挖 + 补线索** | miss 日志 → 夜间深挖 → 写入新 cue | — |
| 睡眠巩固 | **夜间整理任务** | 合并重复、压缩情景、重算强度 | 每天一次 |

> 新增的 **L5 不是一层存储，是"时间预算"**：机器 3 秒就能扫完全库，所以剩下的 57 秒必须花在
> "像人一样换角度想"上，否则那 60 秒就是假的。详见 §8。

## 4. 总体架构

```
                     ┌──────────────────────── 写入（编码） ────────────────────────┐
 用户消息 ──► 显著性打分 ──► 候选池 ──► 去重/冲突消解 ──► 落盘(JSONL) ──► 更新索引
                     │                                                          │
                     └── 显式 memory_remember ──────────────────────────────────┘

                     ┌──────────────────── 回忆（提取，≤60s 硬窗） ─────────────────┐
 忆头(cue) ──► L1 常驻（已在 prompt 里，0ms）
                 │ 未命中
                 ├─► L2 热区缓存                                   ~5ms
                 │ 未命中
                 ├─► L3 长期库（倒排 + 强度加权）                  ~50ms
                 │ 未命中
                 ├─► L4 原始日志（sessionQuery 全文）              1–3s
                 │ 未命中
                 ├─► L5 联想阶梯（换 6 种角度重查，逐步放宽）      3s → 60s
                 │ 仍未命中 / 到点
                 └─► forgotten = true（"想不起来了"）+ 记 miss
                                                    │
                         夜间巩固 ──► 深挖 miss ──► 补 cue / 补强度
```

## 5. 五层记忆：进入条件、容量、淘汰

| 层 | 内容 | 容量/预算 | 进入条件 | 淘汰方式 |
|---|---|---|---|---|
| **L0** | 当前对话 | 模型窗口 | 天然存在 | 会话结束 |
| **L1** | 核心档案：身份、长期偏好、当前主目标、红线 | ≤600 token，条目 ≤15 | `pinned` 或（`importance≥4` 且 `strength≥0.8` 且 `fluency≥0.6`） | 降级回 L3，不删除 |
| **L2** | 当前会话摘要、近 7 天情景、本次预取命中 | ≤1200 token | `strength≥0.5` 或"本会话相关" | 会话结束转 L3 |
| **L3** | 全部提炼条目（事实/情景/方法） | ≤2 万条 | `strength≥0.2` 才默认可检索 | 低于阈值 → `faded`，进 archive/ |
| **L4** | 原始会话日志（原文） | 磁盘上限 | L3 没命中就允许下探 | 永不删（按期归档压缩） |
| **L5** | 联想阶梯（时间预算，不存数据） | ≤60s | L4 仍没命中 | 到点即 `forgotten` |

> 关键点：**层不是存储位置，是"可及性等级"**。同一条目会随时间在 L1→L3→faded 之间移动，数据始终只有一份。

## 6. 记忆条目模型

```jsonc
{
  "id": "mem_20261025_7f3a",
  "kind": "fact",              // fact | preference | episode | procedure | commitment
  "subject": "user",           // user | agent | project | tool | person:<name>
  "text": "记忆主存放在 ~/.dsh/memory（本地盘）；E:\\backup 是外挂素材盘，可能不在",
  "tags": ["环境", "工作盘"],
  "importance": 4,             // 1..5，写入时定
  "confidence": 0.9,           // 来源可信度（亲口说 0.95 / 推断 0.6）

  // ── 可及性（决定"有多容易想起来"）──
  "strength": 0.86,            // 记忆痕迹强度，随时间衰减、随复习增强
  "fluency": 0.92,             // 熟练度：平时多快能想起（0..1，由历史耗时推）
  "avgRecallMs": 180,          // 成功回忆的平均耗时（快速=熟练）
  "mentionCount": 7,           // 被说起 / 写下的次数（复习次数）
  "recallCount": 12,           // 被成功想起的次数
  "failCount": 1,              // 检索过但没命中的次数
  "lastMentionedAt": "2026-10-25T00:10:00+08:00",
  "lastRecalledAt": "2026-10-25T00:10:00+08:00",
  "decayHalfLifeDays": 14,     // 由 importance + 复习次数推出，可单独覆盖
  "pinned": false,
  "status": "active",          // active | faded | superseded | archived

  "source": {                  // 溯源：为什么我记得
    "sessionId": "session-42b25b1d-...",
    "seq": [812, 830],
    "quote": "建议在这个目录里新建一个专门的目录存放"
  },
  "supersedes": null,          // 冲突时指向被覆盖的旧条目
  "cues": ["工作盘", "E盘", "素材放哪"]   // 检索别名（含事后补的线索）
}
```

**为什么带 `source`**：没有溯源的记忆不可信。任何一条都能点回原始会话的那一句；这也是"可审计"和"可纠正"的基础。

**为什么区分 mention / recall**：这两件事在人脑里不是一回事。
"你提过很多次"→ 痕迹深；"我成功想起过很多次"→ 通路顺。前者管 `strength`（记得住），后者管 `fluency`（想得快）。

## 7. 写入链路（编码）

### 7.1 触发点（都用现成事件）
| 时机 | DSH 扩展点 | 做什么 |
|---|---|---|
| 用户消息到达 | `agent/inbox/claimed` | 记入本轮 ring buffer；触发 L2 预取 |
| 每条消息落盘 | `session/event` | 抽取"显式记忆信号"（见 7.2），零 LLM 成本 |
| 一个 turn 结束 | `agent/turn-stopping` | **只入队**，不阻塞；后台 worker 处理 |
| 会话空闲/关闭 | `session/flush` / `session/disposed` | 生成一条 `episode` 摘要 |
| 每天 03:30 | `ctx.timer` 或 `schedule` | 夜间巩固（第 9 节） |

> ⚠️ 关键约束：`agent/turn-stopping` 是 serial 且会被 await。**绝不能在里面同步调模型**，否则每轮都变慢。一律 fire-and-forget 队列 + 单写者。

### 7.2 两级提炼（控成本的核心）
1. **启发式（每轮，0 成本）**：正则/规则命中"记住 / 我喜欢 / 以后都 / 别再 / 我纠正一下 / 我们决定"，
   以及我主动调 `memory_remember`。命中即进候选池，`importance` 由规则给初值。
2. **LLM 提炼（低频，按配置）**：每 N 轮或会话结束时，把最近对话压成 3–8 条候选（带 kind/importance/tags）。
   用便宜的 flash 模型；可在设置里关掉，退化为纯启发式。
3. **文档守卫（2026-10-25 事故后加）**：带 markdown 标题/表格/≥3 个列表项的文本视为"整段粘贴的文档"，
   这类只认显式"记住/备忘"，不自动抽 —— 否则章程里一句"由剩余额度**决定**"就会被记成事实。

### 7.3 成本对照：规则抽取 vs LLM 提炼

先分清三处 token，只有第一处受抽取方式影响：

| 账单 | 纯规则 | 启发式 + LLM | 备注 |
|---|---|---|---|
| **① 抽取（写入）** | **0** | ~2.5k/次，长会话约 5 次 ≈ 12.5k | 按 flash 价，一个会话约千分之几元；**省下的钱几乎可以忽略** |
| **② 注入（每步）** | 600 + 1200，**封顶** | 600 + 1200，**封顶** | 预算硬上限，两种方式**账单一样**；差别只在"同样 600 token 装了多少有用的事" |
| **③ 回忆（每次）** | 返回同样受 1500 封顶 | 同左 | 与抽取方式无关 |

所以准确说法是：**规则抽取确实更省 token，但省的是"写入"那一小段，不是聊天侧的大头。**
真正拉开差距的是质量，不是钱：

- **规则**：零延迟、零依赖、不会因为模型抽风而记错；但抽得糙（漏掉"这事其实很重要"、把寒暄当偏好）、
  容易存**长原句**（把整段对话抄进去），也更容易误报 → 条目膨胀 → 索引里噪声多。
- **LLM**：能把"你上次说那个盘满了、想换个地方放素材"压成"素材要换盘（2026-10）"，
  信息密度高、噪声少；代价是每会话几秒钟延迟和一点点钱，且抽错了不容易发现。

**结论 / 默认建议**：M1 走**纯规则 + 短句模板**——规则只截"信号词所在的这一小句"（≤60 字 + 指回 `source`），
不抄整段。这样写入 0 token、注入也短，兼顾两端。等跑一段时间，用 `stats.json` 里的
"命中率 / 误抽率 / 平均条目长度"再决定要不要开 LLM。

### 7.4 显著性打分（importance）
`importance = clamp(1..5, 基础分 + 修正项)`
- 显式要求记住 **+2**｜用户纠正我 **+2**｜重复出现 **+1**｜涉及身份/偏好/承诺/金额 **+2**
- 一次性的工具输出、寒暄、临时路径 **−2**
- 超过 3 次被回忆 **+1**（越用越重要）

### 7.5 复习：提及与回忆都会加深印象（v0.2 新增）

每发生一次 **提及**（写到/说到这条）或一次 **成功回忆**，都算"复习"，按**间隔效应**给强度加分：

```
Δt      = 距上次复习的天数
spacing = Δt / (1 + Δt)                              # 间隔越久，单次复习越值钱（0.1 ~ 1）
gain    = reinforceGain × (importance/3) × spacing
          × (回忆时再乘 fluencyFactor，见 §9.2)
strength = strength + gain × (1 - strength)           # 上界 1，边际递减
```

三条推论，正是你要的效果：
- **同一分钟内反复提**：`spacing≈0.1`，几乎不涨——人也不会因为连说三遍就记三倍。
- **隔几天再提一次**：`spacing≈0.8`，明显加深——这才是"经常提及"真正的作用。
- **很久不提**：`strength` 只降不升，自然滑向 faded——没有复习，就没有回血。

### 7.6 去重与冲突
- 去重：文本归一化后 bigram Jaccard ≥ 0.8 → 视为同一条，只更新计数与时间。
- 冲突：同 `subject + 谓词` 的新事实 → 新条目 `supersedes=旧id`，旧条目 `status=superseded`（**保留，可回溯**）。

## 8. 回忆链路（提取）—— 含 60 秒硬窗（v0.2 重点）

### 8.1 忆头（cue）从哪来
- 模型显式调 `memory_recall({query})`；
- 用户消息到达时自动生成 cue（`autoRecall: fast` 只做 L2 预取）；
- cue 支持**关键词扩展**：query 里的简称（"小满"）→ 用 `cues` 字段里的别名一起查。

### 8.2 一次回忆 = 一个有 60 秒预算的"episode"

```
recall(cue):
  episode = { id, startedAt, deadline = startedAt + 60s, rungs: [] }
  R1  L1 常驻           已在 prompt                    ~0ms
  R2  L2 热区缓存                                       ~5ms
  R3  L3 倒排（强度加权）                                ~50ms
  R4  L4 原文全文（sessionQuery）                        1–3s
  ── 到这里机器已经"能查的都查完了"，剩下 57 秒花在联想 ──
  R5  联想阶梯（纯规则，**不调模型**；按成本递增，每次放宽一点）：
      a) cue 扩写：内置同义词表 + 条目 cues 别名 + bigram 变体
      b) 换字段：按人物、按项目、按时间窗、按 kind 重排
      c) 读候选：把 L4 命中的前 3 段原文整段读进来再判一次
      d) 规则判相关：关键词重合度 + 字段一致性（人/项目/时间对得上）+ 强度阈值，
         本地打分排序；不做语义推断，判不出来就算判不出来
      e) 放松：允许 include_faded，允许低强度条目
      f) 跨会话：把"最可能相关的那几个旧会话"整段扫一遍
  ── deadline 到 ──
  if 任何一级命中: return hits（带 layer_used / elapsed_ms）
  else:            forgotten = true; missLog.append(cue); return "想不起来了"
```

### 8.3 不阻塞对话：两段式（**已定 D1**）

一次阻塞 60 秒在聊天里是不能接受的。所以按"先应一声，想起来了再接着回"来：

| 阶段 | 时长 | 行为 |
|---|---|---|
| **A 快速段** | ≤3 s | 直达 R1–R4。命中就正常回答；没命中就**立即返回** `pending=true + episode_id` |
| **A 开口** | 立即 | 我先回你一句（"这个我得想一下" / 先继续聊别的），不干等 |
| **B 联想段** | 到 60 s | 后台继续跑 R5（纯规则）。我这期间可以正常说话 |
| **B 命中** | 任意时刻 | 把它当成"我本来就知道"接着回答；**不说"我想起来了"**（D5） |
| **B 到点** | 60 s | `forgotten=true`，写 miss，之后不再重复挖同一个 cue |

- `recallMode` 默认就是 `'async'`（D1）。`blocking` 只作为调试/核对用选项保留，不默认开。
- 无论哪种模式，**60 秒是同一个硬截止**；区别只在"这 60 秒里我是否已经开口"。

> **D5：命中不播报**。回忆成功的表现不是"我想起来了"，而是**回答里直接带着那件事**。
> 例：你问"这次还是放 本地盘吗" → 我答"本地盘，`~/.dsh/memory`；外挂盘不在也不影响"，而不是
> "我想起来了，你之前说过记忆放在 本地盘…"。只有你问"你怎么知道"时，才说"你之前说过"。
> 这条同时写进了 L1 注入文案和 `memory_recall` / `memory_recall_wait` 的工具描述，不靠自觉。

> **规则联想的代价（D2 的已知取舍）**：不调模型 = "显卡"和"GPU"这种同义只能靠同义词表接上，
> 接不上就真的找不到。补偿手段有三条：① `cues` 别名随每次成功回忆自动积累；
> ② 内置同义词表可手工编辑（`synonyms.json`）；③ 夜间巩固把 miss 的 cue 拿去 L4 再挖，挖到就补进 `cues`。
> 如果哪天你觉得"想不起来"太多，把 `recall.associate.allowModel` 改成 `true` 就能启用第 d 步的模型判定，其余不变。

### 8.4 "忘了"的含义
- `forgotten` 只针对**这一次、这个 cue**，不等于条目被删。换个说法、换个时间，仍可能被另一条线索捞起来。
- 到点判忘后：`failCount++`，写 `misses.jsonl`；**不扣 strength**（避免"一次没想起就永久变傻"）。
- 老失败、后来被别的 cue 想起来的条目 → 把当年失败的 cue 补进 `cues`（"事后想起"），下次同问法秒中。

### 8.5 排序权重（初值，可调）
`score = 0.40·文本匹配 + 0.25·strength + 0.15·fluency + 0.10·importance + 0.05·时间新鲜度 + 0.05·pinned`

- **相关度闸门**：这批权重里 strength/fluency/importance/新鲜度加起来有 ~0.45 的基线，
  光看总分的话，任何刚写进来的条目都能挤进结果（实测问"电饭煲放哪"会返回"记忆存在 本地盘"）。
  所以第 0 层额外要求 `文本匹配 ≥ 0.08` 才算命中。
- **阶梯只放宽"搜哪里"，不放宽"相关度底线"**：2026-10-25 出过一次事故 —— 闸门随阶梯一起放松
  （0.08 → 0.04 → 0.02），6 秒后拿两条 `text_match≈0.02` 的无关记忆当答案返回了。
  编造比"想不起来"更糟，所以底线恒为 0.08（线性扫 0.12）。
- **罕见词例外**：命中"只出现在少数条目里的多字词"（如"冷备"）可以把底线放宽到 0.04；
  单字（放/在/的）不算 —— 小语料库里每个字都只出现在一两条里，不加这条限制等于没有闸门。
- **别名只在强匹配时学习**：只有 `text_match ≥ 0.5` 的"费劲想起"才把这个问法写进 `cues`。
  否则一次错误命中会把"电饭煲放哪了"变成"记忆存在 本地盘"的别名，错误会自我强化（真发生过，已清理）。
- **同义词多变体**：不能把所有同义词一次拼进查询——分母（查询总 idf）被稀释，0.2 的匹配会被摊薄到 0.05。
  实现是"原句 + 每个同义词单独拼一次"，各自查、按 id 取最大分。

### 8.6 主动浮现（priming）
当 cue 与某条目的历史匹配极强（`score≥0.9` 且该条目 `fluency≥0.8`），不等我调工具，**直接进 L2 预取**——
相当于"听到一个名字，那个人立刻浮现在眼前"。这是"经常提及 → 提及时很轻松想起"的落地点。

## 9. 遗忘与巩固

### 9.1 衰减公式（v0.2 调整）
```
S(天) = baseHalfLife × 2^(importance-3) × (1 + 0.5·ln(1+recallCount)) × (1 + 0.3·ln(1+mentionCount))
R(t)  = exp(-Δt / S)          # Δt = 距最近一次复习（提及或回忆）的天数
strength = R(t)               # 命中/提及时由 §7.5 拉回
```
- `baseHalfLife = 7` 天（importance=3）；importance=5 → 28 天，importance=1 → 1.75 天。
- **小事（importance 1–2）半衰期 1.75–3.5 天**：一周不提就淡出 L2，两周 faded —— 这就是"慢慢降低印象直到遗忘"。
- **常用条目**：`recallCount` / `mentionCount` 高 → 半衰期被对数拉长，且每次提及都回血 → "越用越牢"。
- `pinned` 条目不衰减（刻进长期记忆）。

### 9.2 熟练度（fluency）—— "轻松想起来"的度量
```
本次回忆耗时 latency（从 episode 开始到命中）
fluencyFactor = 1 / (1 + latency_s / 2)      # 0.5s → 0.8；5s → 0.29；30s → 0.06
fluency = 0.7·fluency + 0.3·fluencyFactor     # 指数滑动，最近几次权重更大
```
- **秒回**（<1s）：fluency 高 → 排序靠前，更容易进 L1/L2，下次更快。
- **翻了半分钟才想起**：gain 很小，fluency 低 → 下次仍然费劲（"勉强记住"）。
- 这就是"回忆难度"本身：不是布尔值，是 `latency` 的历史分布。

### 9.3 夜间巩固（03:30，一次跑完）
1. 重算所有条目 strength，低于阈值的 `status=faded` 并移入 `archive/`（仍在磁盘）。
2. 合并重复条目（同 subject+谓词、文本相似），计数相加。
3. 把最近 24h 的会话压成 1 条 `episode`。
4. 拿 miss 日志做一次 L4 深挖，补 `cues`（见 8.4）。
5. 统计：命中率、平均下沉层数、平均回忆耗时、60 秒超时率、注入 token 数 → 写 `stats.json`。

### 9.4 归档而非删除
- `archive/` 里的条目**不参与默认检索**，但 `recall(layer='deep', include_faded=true)` 仍可捞出。
- 真删除只有一条路：`memory_forget({mode:'purge'})`。**记忆归我自己维护，不用请示**（D7），但要写墓碑留痕；面板里人类侧保留两段点击防手滑。

## 11. 存储与性能

### 位置（✅ D3 已定）
```
~/.dsh/memory\          ← 主存（本地盘，D: 当前可用 298 GB）
  entries.jsonl        # 主库，append-only（不重写，坏了可截断）
  misses.jsonl         # 回忆失败日志（60 秒到点的 cue）
  recall-log.jsonl     # 每次回忆 episode：走了几级、耗时、命中与否（用来算 fluency）
  index.json           # 倒排索引快照（启动时缺失/过期则重建）
  synonyms.json        # 同义词/别名表（D2 规则联想的弹药，可手工编辑）
  stats.json
  config.json
  episodes\2026-10.jsonl
  archive\faded-2026Q4.jsonl
  backups\             # 本机快照
```
- 放在本地主存目录：**随 DSH 本体一起备份、不依赖外挂盘**。
- **外挂盘只做可选冷备**：挂载时夜间 rsync 一份过去；不在时**不报错、不阻塞、不降级**，
  主流程完全不看它（不做符号链接、不把索引放过去）。
- 记忆目录在项目工作区（`gzq`）之外，不会混进任何 git 仓库。

### 索引
- 中文：**bigram 倒排**（"工作盘" → 工作/作盘）；英文/数字：词 + 前缀。
- 辅助索引：`kind`、`subject`、`tags`、`status`、时间桶、`fluency` 分桶。
- 规模：2 万条 ≈ 5–15 MB JSON，倒排常驻内存约 20–40 MB → 完全可接受，无需数据库。
- 启动加载：读 JSONL → 建索引，2 万条约 200–400 ms（后台完成，不阻塞 agent）。

### 预算（硬上限）
| 项 | 默认 | 说明 |
|---|---|---|
| L1 注入 | 600 token | 超了按 strength 截断，截断处提示"还有 N 条在长期库" |
| L2 注入 | 1200 token | 仅本会话相关 |
| 单次 recall 返回 | 1500 token | 超了只返回摘要 + id，让我再按需展开 |
| 单次回忆总时长 | **60 s** | 到点即 `forgotten`，不延长 |
| 联想段模型调用 | **0 次** | ✅ D2 已定：纯规则；仅当 `allowModel=true` 时才放开（≤3 次） |
| 提炼调用 | 每会话 ≤2 次 | 可关 |

## 15. 安全与边界

1. **只存本机**，不出网；不进日志、不进仓库（`~/.dsh/memory` 不在项目目录）。
2. **敏感信息默认不记**：Cookie、token、密码、支付信息（正则拦截 + 配置可加）。
3. **可解释**：每条记忆都有 `source`，能点回原话；`why` 字段解释为什么被召回。
4. **可纠正**：你说"不对，是 X" → 新条目覆盖旧条目（supersede），旧的不删但不再参与排序。
5. **一键忘记**：UI 或 `memory_forget`；`purge` 是唯一真删，由我自己判断（保留墓碑，可带删除原因）。
6. **不污染指令层**：记忆注入放在独立 section（`memory:*`），绝不写进 `AGENTS.md` / 章程，不能覆盖你的明确指示。
